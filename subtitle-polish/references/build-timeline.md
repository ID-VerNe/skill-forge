# 从片源建立可信时间轴（翻译前的第 0 步）

本文件说明一件事：**时间轴应该在翻译之前建立，而不是交付前抢救。**

这条流水线原来是「翻译 → 审校 → 发现偏轴 → 回头修」。修的那一步叫**恢复**：参照物是"原来那条正确的时间轴"，而它已经丢了，只能从音频反推，反推就有精度上限（实测 85~90%）。

前置之后叫**建立**：参照物是音频本身，可以直接测。而且多数情况下根本不用建——片源里就躺着一条同轴的。

---

## 1. 四步

```bash
# ① 看片源里有什么
python scripts/extract_subs.py --media S06E01.mkv --list

# ② 抽出来（默认转 srt，避开样式名不是「英文」的坑）
python scripts/extract_subs.py --media S06E01.mkv \
    --out .subtitle-polish/streams --format srt

# ③ 判轴：哪条与音频是一伙的（--write-credential 顺手把凭据写掉）
python scripts/align_audit.py --sub streams/S06E01.s0.uk.srt \
    --asr-words asr_words_E01.json \
    --compare streams/S06E01.s1.us.srt \
    --compare streams/S06E01.s2.uk.sdh.srt \
    --compare streams/S06E01.s3.us.sdh.srt \
    --write-credential --source-index 0 --source-family UK

# ④ 只有在「没有同轴流」时才需要对轴（见 §3）

# ⑤ 开工前确认凭据有效（毫秒级；翻译 pipeline 从这一步之后接手）
python scripts/timeline_gate.py streams/S06E01.s0.uk.srt --media S06E01.mkv
```

第 ③ 步产出的 `<episode>.ts.json` 就是**交给下一环的凭证**：翻译 pipeline 不必再验一遍，
但也不能在凭据缺失时声称轴是对的。字段与失效规则见 `timeline-credential.md`。

---

## 2. 判轴优先：多数片源本来就有同轴流

E01 的片源里 4 条字幕流，同一段音频分别比对：

| 流 | 中位 | MAD | 斜率 | 全长漂移 | 结论 |
|---|---|---|---|---|---|
| s0 **UK 正片** | −0.04 | **0.22** | +0.000117 | **+0.31 s** | 同轴，直接可用 |
| s1 US 正片 | +0.78 | 0.62 | +0.000875 | +2.28 s | 异轴 |
| s2 UK·SDH | −0.04 | **0.22** | +0.000117 | +0.30 s | 同轴 |
| s3 US·SDH | +0.78 | 0.62 | +0.000875 | +2.28 s | 异轴 |

MAD 差 3 倍，一眼可辨。UK 流全长只偏 0.31 s，**已经在验收阈值内，不需要任何对齐**。

这一步的价值不在于"修"，而在于**避免修**：盲目拿 US 流去对齐，等于用 15% 的恢复误差换一个本来就 0 误差的结果。

> 反面教材：上一轮正是没做这一步——直接拿扒来的国际版字幕开工，翻译审校全部做完才被压制方发现整集偏 2.9 s。

---

## 3. 什么时候真的需要对轴

- 片源里**只有异轴流**（实测 E07/E08：两条内嵌流都是国际版轴，音频是英国版剪辑）
- 外部下载的 SRT 与片源不是同一剪辑版本
- 自制 / OCR / ASR 生成的字幕，没有可靠时间轴

这时的做法与精度见下节。

---

## 4. 对轴的精度上限

以「输入偏 1.5~1.8 s」的两种典型形态做注入测试：

| 形态 | 一轮修正后残差（极差） | 对真值偏差（中位/P95） |
|---|---|---|
| 剪辑点阶跃（3 处，末端 +1.57 s） | 0.230 s | 0.09 / 0.20 s |
| 纯线性（末端 +1.83 s） | 0.170 s | 0.14 / 0.25 s |

**一轮恢复 85~90%，残余 0.1~0.2 s。** 阶梯型与线性型恢复率一致（88% / 86%），是「随位移量成比例地少测」，不是某种形态的特例；机制未定位（可能是块内对齐把 token 拉进给定音频段，也可能是首词锚点的系统偏置）。

**二轮不要做。** 对已修过的样本再测一次，残余极差 0.230 s、斜率 −0.11 s，与一轮后复测逐位相同（中位 +0.020 / MAD 0.120）——聚合指标可复现到 0.01 s，说明残差是真的；但二轮拟合出的可修量只有 **0.10 s，形态是一个孤立阶跃**，那是拟合噪声。施加它只会引入假阶跃。

**0.1~0.2 s 就是这条链路的终点**，低于人眼可察觉阈，也优于人工对轴的原始交付件（实测原始 UK 流本身也有 0.31 s 漂移）。

要更紧，唯一的路是**换输入**：§2 的判轴，或者要求片源提供同轴字幕流。继续在对齐算法上加轮次没有收益。

---

## 5. 为什么不建议"翻译完再对齐"

1. **参照物丢了**。翻译后只能恢复，恢复的基准是猜的；而翻译前建立，基准是音频，可直接测。
2. **条数会变**。翻译与审校可能合并/拆分条目，此时按条配对的对齐脚本会失配（实测 E04 的 SRT 750 块 vs 英文轨 749 条）。虽然 `align_patch` 用纯时间函数避开了这个坑，但条目边界已被改动，偏移函数未必还能贴合。
3. **成本更高**。翻译+审校做完才发现偏轴，返工面覆盖全部文本；前置只需在一条单语 SRT 上动时间。

---

## 6. 前置之后，交付前仍要验

前置解决的是"时间轴从哪来"，不解决"最终文件对不对"。三条判据照旧（见 `align-audit.md` §9）：

```bash
verify_fixes 0 失败  +  cross_check 全绿  +  align_audit 极差达标
```

差别在于：前置之后，第三条通常一次就过，而不是变成一次返工。
