# 对齐审计（时间轴）

本文件回答一个问题：**字幕文本改对了，但它出现在对的时间吗？**

结案时若只看 `verify_fixes` + `cross_check`，答案是「不知道」——这两个脚本一个字都不读时间字段。实测一批 8 集双语成品全流程绿灯交付，压制方反馈「所有集都对不上轴，越往后偏得越多」，回头用音频测出 3 集各偏 2.4~2.9 秒。

---

## 1. 为什么必须对音频，不能对字幕

「字幕 vs 本片内嵌字幕流」是最容易想到的基准，也是**最危险的**：它默认了「内嵌流与音频同步」，而这个前提常常不成立。

实测同一套 WEB-DL（8 集），内嵌流与音频的关系：

| 集 | 对音频的累积漂移 | 判定 |
|---|---|---|
| E02–E06 | ≤ 0.41 s | 内嵌流可信 |
| E01 | **+2.44 s**（4 处 +0.48 s 阶跃） | 内嵌流本身错轴 |
| E07 | **+2.79 s** | 内嵌流本身错轴 |
| E08 | **+2.91 s** | 两条内嵌流都错轴 |

根因：**音频是英国版剪辑，字幕却取自国际版（US）**。两版在剪辑点相差 0.48 s 的整数倍，逐段累积成「越往后越偏」。

E01 三轴对照（同一段音频，分别比对各候选基准）：

| 比对对象 | 中位 | MAD | 斜率 | 全长漂移 |
|---|---|---|---|---|
| ASS 终稿（修前） | +0.76 | 0.64 | +0.000932 | **+2.44 s** |
| MKV idx3（US / 无标题流） | +0.76 | 0.64 | +0.000932 | **+2.44 s** |
| MKV idx2（UK 流） | −0.06 | **0.24** | +0.000158 | +0.41 s |

ASS 与 US 流数字逐位重合 → ASS 就是扒的 US 轴。**拿它当基准，校验再严也只是自证。**

> 结论：对齐审计的唯一可信基准是**音频本身**。字幕流最多用来做「轴归属判定」的候选。

---

## 2. delta 与判据

```
delta = 语音发声时刻 − 字幕显示时刻
```

正常应 **+0.10 ~ +0.20 s**（字幕略早于发声，观众才读得完）。

**判据不是「delta 是否为 0」，而是「分时段 delta 中位数是否平坦」。**

原因：delta 的绝对值里混着三层东西——字幕提前量（设计使然，+0.1~0.2）、引擎系统偏置（±0.3，见 §4）、真实漂移。只有**窗间中位数的极差**（跨时段是否越走越偏）才是纯的漂移信号。

`align_audit.py` 输出的四个数，各管一件事：

| 指标 | 含义 | 怎么用 |
|---|---|---|
| delta 中位 | 整集系统性提前/滞后 | 参考，**不作判据**（含引擎偏置） |
| MAD | 单条 delta 的离散度 | 衡量「文本与音频一致度 + 引擎精度」，>0.5 说明对齐质量差 |
| 斜率 × 时长 | 线性累积漂移 | 判断能否用线性补偿一次性解决 |
| **分时段中位极差** | **最大系统性残差** | **主判据** |

阈值按引擎取（`--tol` 可覆盖）：

| 引擎 | 默认阈值 | 依据 |
|---|---|---|
| `whisper` | 0.50 s | 实测从未改动过的集也有 0.30 s 极差 |
| `qwen` | 0.30 s | 实测干净集 0.08~0.18 s |

---

## 3. 引擎选择：粗筛与精测

两个引擎归一到同一种词级时间戳，统计口径完全一致，差别在精度。

| 集 | whisper MAD | qwen MAD | whisper 极差 | qwen 极差 |
|---|---|---|---|---|
| E01 | 0.200 | 0.180 | 0.280 | 0.35¹ |
| E02 | 0.170 | **0.120** | 0.300 | 0.18 |
| E03 | 0.200 | **0.120** | 0.440 | 0.26 |
| E04 | 0.180 | **0.095** | 0.260 | **0.08** |
| E05 | 0.180 | 0.140 | 0.410 | 0.46¹ |
| E06 | 0.230 | 0.160 | 0.380 | 0.16 |
| E07 | 0.210 | 0.158 | 0.350 | 0.27 |
| E08 | 0.240 | 0.220 | 0.560 | 0.30 |

¹ 被个别样本稀少的窗口拉大，剔除后约 0.19 / 0.20。

**用法：**

- **whisper 是粗筛**。MAD 0.17~0.24，能稳定抓 >0.5 s 的错轴（E01/E07/E08 的 2.4~2.9 s 一眼可见），但 0.2 s 级残差分不清。
- **qwen 是精测**。MAD 0.095~0.22，能分辨 0.2 s 级残差——E04 的 +0.21 s 线性漂移就是它抓到的，whisper 当时报 −0.05 s。

**两条禁令：**

1. **不要用 whisper 的斜率/中位当补偿量。** 实测 E08：whisper 中位 −0.40 s，qwen 中位 −0.08 s，差 0.32 s——这是引擎系统偏置，不是字幕偏。按 whisper 补会凭空造出 0.3 s 误差。
2. **whisper 判 FAIL 不等于要改轴。** 极差落在 0.3~0.5 s 区间几乎全是噪声，先换 qwen 复核再动手。反之 whisper 判 PASS 只说明没有粗错，不代表亚 0.3 s 级也对。

> 为什么不用 whisperX 的 `align()`：它按 segment 的 `start`/`end` **切音频**（`audio[:, f1:f2]`）再跑 wav2vec2。输入时间戳偏 2 s，切出来的窗口就是错的，结果跟着错——它对「轴已经错了」的字幕无能为力。Qwen3-ForcedAligner 的 `align(audio, text)` **不接收时间窗**，是「整段音频 + 整段文本」的全局对齐，原轴偏 3 s 也照样还原真实发声时刻。

## 4. 轴归属判定

多版本剪辑的项目，先判「哪条内嵌流跟音频是一伙的」，再决定能不能拿它当参考流。

```bash
python scripts/align_audit.py --sub 终稿.ass --asr-words asr_words.json \
    --compare uk.ass --compare us.ass
```

同一段音频分别与每个候选比对，**MAD 最小者才是可信基线**（E01：UK 0.24 vs US 0.64，一眼可辨）。输出里的「轴归属对比」表直接给出结论。

也可以反过来验：拿 `align_patch.py --ref <候选流>` 干跑，若偏移是**平滑的单一值**或 0，说明这条流和当前字幕同轴；若打出**整数处阶跃**，说明它是另一版剪辑。

---

## 5. 三种修复手段

| 现象 | 手段 | 命令 |
|---|---|---|
| 线性漂移，无阶跃 | 线性补偿 `off(t)=k(t−t0)` | `--slope K` |
| 剪辑点阶跃 + 有可信参考流 | 逐条重定时 | `--ref ref.ass` |
| 剪辑点阶跃 + 无参考流 | 分段常数曲线 | `--spec audit.json` |

**线性补偿**：`--origin` 默认取首条字幕起点，保证开头不动、只补末端。实测 E01 +0.000096（末端 +0.25 s）、E04 +0.000081（+0.21 s）、E07 −0.000087（−0.23 s）。

**逐条重定时**：用英文文本 LCS 建映射，未匹配条按前后锚点的偏移插值（不是按索引平均，避免阶跃处跳空）。E01 实测 728/728 全匹配，打出 4 处 +0.48 s 阶跃，与手工排查结果一致。

**分段曲线**：`align_audit --json` 里带 `curve` 字段（BIC 选段数 + **单调不减**约束 + **首段归零**）。两个约束都不能省：

- 单调不减：剪辑点只会让偏移单向累加，不会回退；
- 首段归零：对齐器与字幕起点存在系统性偏置（实测 base −0.279 s），不减去就会把整集平推一段，反而制造新偏移。

> 判 PASS 的集不输出 curve。残余多是噪声，拟合出的曲线没有物理意义，误用会平白制造偏移。

---

## 6. 为什么改时间要独立于改文本

`align_patch.py` 刻意**不依赖 srt_id 配对**：`off(t)` 是纯时间函数，对 ASS 英文轨、中文轨、配套 SRT 各自独立施加即可。

这避开了一个真实的坑：E04 的 SRT 有 750 块、英文轨 749 条，按条配对的脚本直接跳过 SRT（`[skip SRT] 750 vs 749`），结果 ASS 改了 SRT 没改，两套不同轴。用纯时间函数施加，条数不等完全不影响。

写盘也只替换 `Dialogue:` 行的 Start/End 两个字段，其余字节原样保留（实测 1732 行变动，去掉时间字段后 0 处差异）——不重排样式段、不丢注释、不动 `[Aegisub Project Garbage]`。

---

## 7. 三个必须处理的坑

**① 分块切在句中**。强制对齐按块喂文本，块边界切断了句子，该行就会锚到块首——实测 `ass 602.12 → align 600.00`，差 −2.12 s。`--chunk` 的边界必须在目标块长 ±45 s 内找**最大字幕间隙**，前后再留 2 s 余量。

**② 离群点污染回归**。ASR 听错、译文漏词、片头片尾噪声的 delta 与时间轴无关，留着会把斜率拉飞：E08 首跑得 `min −43.46 s`、斜率 +0.000660，真实值 −0.000080。必须按 `|delta − 中位| > max(1.5, 6×MAD)` 剔除（实测每集剔 34~59 条）。

**③ 把「内嵌流对齐」当验收**。见 §1。这条最贵：上一轮 handoff 就是这么得出「E02–E08 全部 0 偏差」的，错了整整一轮。

## 8. 命令清单

```bash
# ① 审计（视频直接给，自动抽 16k 单声道）
python scripts/align_audit.py --sub S06E01.eng.ass --media S06E01.mkv \
    --report .subtitle-polish/reports/align-E01.md --json .subtitle-polish/align/E01.json

# ② 粗筛过了、要精测 → 换引擎
python scripts/align_audit.py --sub S06E01.eng.ass --media S06E01.mkv \
    --engine qwen --model /path/to/qwen3-aligner-0.6b

# ③ 轴归属
python scripts/align_audit.py --sub 终稿.ass --asr-words w.json \
    --compare uk.ass --compare us.ass

# ④ 修复（默认 dry-run，加 --write 生效，自动 .bak）
python scripts/align_patch.py --sub a.ass --sub a.srt --slope 0.000096 --write
python scripts/align_patch.py --sub a.ass --ref uk.ass --write --emit-spec step.json
python scripts/align_patch.py --sub a.srt --spec step.json --write

# ⑤ 复测（同一份 asr-words 缓存，秒出）
python scripts/align_audit.py --sub a.ass --asr-words w.json
```

模型目录：whisper 用 `large-v3`（首次会自动下载或指定本地目录）；qwen 需本地 `Qwen3-ForcedAligner-0.6B`。

> **HF 缓存目录陷阱**：`~/.cache/huggingface/hub/models--*/snapshots/*` 里全是符号链接，`transformers` 的 `cached_files` 会把路径当 repo_id 校验，报 `Repo id must use alphanumeric chars...`。把 snapshot 内容复制成实体目录再用（1.7 GB，`shutil.copyfile` 约 1.4 s）。

## 9. 结案口径

字幕交付前三条都要过：

```bash
python scripts/verify_fixes.py --batch-id <ts>    # 改的东西写进去了
python scripts/cross_check.py  --batch-id <ts>    # 写进去的是这句该有的译文
python scripts/align_audit.py  --sub <ass> --media <片源>   # 写进去的东西在对的时间
```

第三条**不能省**，也不能用「对过内嵌字幕流」代替。上一轮的教训是：前两条全绿、8 集全"通过"，实际 3 集偏 2.4~2.9 秒。

报告里必须写明「本次验证覆盖范围」——测了几集、用的哪个引擎、极差多少，别让「N 通过」被读成「全文正确」。
