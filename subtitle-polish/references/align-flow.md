# 对轴流程（A0→A5）

本文件是 subtitle-polish **对轴模式**的流程骨架。主 `SKILL.md` 路由到此。

对轴模式**不碰文本**。它只回答一个问题：这条字幕跟音频对不对得上；对不上，改时间字段。
文本的问题（错译、漏译、专名）属于自动审校模式，别混进来——混进来的后果是「改时间」和「改文本」
两批改动在同一份 ASS 上交替落盘，回滚时谁也退不干净。

```bash
/subtitle-polish 对轴:<ass> 片源是 <mkv/wav>
```

---

## 读哪里

本文件只讲「先做什么后做什么、在哪儿停」。具体判据与命令参数不在这里：

| 想知道 | 去哪 |
|---|---|
| 为什么必须对音频、delta 怎么算、阈值多少、双引擎怎么选 | `align-audit.md` §1–§3 |
| 轴归属判定（这条流是不是跟音频一伙的） | `align-audit.md` §4 |
| 三种修复手段（线性 / 重定时 / 分段曲线）怎么选 | `align-audit.md` §5 |
| 片源里本来就有同轴流、要不要先判轴 | `build-timeline.md` §2–§3 |
| 凭据字段、失效规则、四态含义 | `timeline-credential.md` |
| 秒级结构体检（不加载模型） | `align-audit.md` §12 |

**先读 `build-timeline.md` §2 再动手。** 多数片源里躺着一条同轴的字幕流，直接用它比对齐更准，
因为对齐有 85~90% 的恢复上限，而同轴流是 0 误差。

---

## A0. 确认有片源

对轴模式的**唯一硬前置**是片源（MKV/MP4，或已抽好的 wav）。没有片源就停下，告知「对轴必须有片源」，
不要拿 ASS 自己的时间戳去猜。

同时确认这次到底要不要对轴：

- 用户说「看看时间对不对」→ 走 A1 审计，不改任何东西。
- 用户说「偏了，修一下」→ 走 A1 → A2 → A3。
- 用户手上只有片源、还没字幕 → 那是 `build-timeline.md` 的活（先判轴抽流），不是对轴。

---

## A1. 审计（只读）

```bash
python scripts/precheck_timeline.py <ass>                     # L0，秒级，先扫结构硬伤
python scripts/align_audit.py --sub <ass> --media <片源> \
       --write-credential                                      # 主判据
```

两个脚本的分工是「便宜的先跑」：L0 不加载模型，能秒级抓出时间轴倒退、零长、跳变这类结构问题；
结构都不成立时再上 ASR 是白烧显存。

结论四态，**`UNVERIFIED` 不是通过，是没验**：

| 判定 | 退出码 | 含义 | 下一步 |
|---|---|---|---|
| PASS | 0 | 分时段中位极差在阈值内 | 结束，出凭据。**不要为了「更保险」再对齐一次**——判 PASS 的集残余是噪声，施加曲线只会制造新偏移 |
| FAIL | 2 | 确实偏了 | 进 A2 |
| UNVERIFIED | 3 | 没验成（缺模型/缺音频/凭据过期） | 报告里明写「未验时间轴」，不许默认它对 |
| AMBIGUOUS | 4 | 两档分块结论不一致 | 停下问人，不许当 PASS 结案 |

> **不要用片源内嵌字幕流代替音频。** 内嵌流自己可能就错轴——E01 的 US 流整集偏 2.28 s，
> 拿它当基准等于把错的当对的。判据必须来自音频。

## A2. 判轴：有没有现成的同轴流

只在 A1 判 FAIL 时才有意义，而且要在**动手修之前**问这一句。

```bash
python scripts/extract_subs.py --media <片源> --list
python scripts/extract_subs.py --media <片源> --out .subtitle-polish/streams --axis
```

`--axis` 会对全部候选流各做一次 ASR 比对，直接给出「哪条跟音频是一伙的」。

| 结果 | 走什么 |
|---|---|
| 存在同轴流，且它就是我们要的那条 | 直接替换/以它为基准，**不进 A3**。0 误差胜过 85~90% |
| 存在同轴流，但语言/版本不对 | 进 A3，把同轴流当 `--ref` 做逐条重定时 |
| 没有任何同轴流 | 进 A3，只能靠音频反推 |

判轴的价值不在「修」，在**避免修**。

---

## A3. 修（默认 dry-run）

按 A1/§5 的形态选手段，三选一，不要混用：

| 现象 | 手段 | 参数 |
|---|---|---|
| 线性漂移，无阶跃 | 线性补偿 | `--slope K` |
| 剪辑点阶跃 + 有可信参考流 | 逐条重定时 | `--ref ref.ass` |
| 剪辑点阶跃 + 无参考流 | 分段常数曲线 | `--spec audit.json` |

三条硬规则：

1. **默认 dry-run，看预览再 `--write`。** 写盘只替换 `Dialogue:` 行的时间字段，其余字节原样。
2. **一次只施加一种手段。** 先线性再曲线的叠加会把两者的残差一起放大，且无法归因。
3. **精度的终点是 0.1~0.2 s。** 二轮不值得做——实测第二轮拟合出的「可修量」0.10 s 是拟合噪声，
   施加它只会平白引入一个假阶跃。想要更紧，回去改输入（A2），不要在对齐算法上加轮次。

## A4. 记账（`--write` 时自动，别手动补）

`align_patch --write` 之后必须三件事齐全，缺一件就会留下「看不见的债」：

| 动作 | 缺了会怎样 |
|---|---|
| 写 `log.jsonl`（`action=retime_curve`） | `--rollback batch=` 回滚完文本、时间还错着，**回滚本身变成新的错误** |
| 让时间轴凭据失效 | 闸门不转 UNVERIFIED，后续流程会拿旧凭据当「已验」 |
| 记 `backups.jsonl` | `.bak` 不进 git，事后无法枚举、对不上是哪次操作 |

撤销一次曲线：

```bash
python scripts/align_patch.py --sub <ass> --revert        # 整文件逐字节还原
```

`--revert` 只退**最近一次**（它从 log 里找最后一条 `retime_curve` 的备份）。
这条路正是「A3 一次只施加一种手段」的理由之一：连施两次后想退回第一步，
要么连按两次 `--revert`（第二次的备份是第一次的结果，理论上能退回去，但中间态已经被覆盖），
要么从 `.bak` 手工还原。一次一种，退起来是一步。

**不要用 `apply_fixes --rollback` 撤曲线**：那是按行反向加回去，会累积浮点误差，
也处理不了当时被钳位到 0 的条目。

## A5. 复测 + 凭据

```bash
python scripts/align_audit.py --sub <ass> --media <片源> --write-credential   # 同缓存，秒出
python scripts/timeline_gate.py <ass> --media <片源>                          # 毫秒级闸门
```

复测用同一份 asr-words 缓存，不必重新 ASR。闸门只读凭据，不跑模型。

交付口径（三句话，缺一句都算没验完）：

- 分时段中位极差 —— 证明偏差在阈值内；
- 全长漂移（首尾取中位之差）—— 证明没有整体推走一段；
- `retime_curve` 的复测结论 —— 证明施加减的是**应该减的量**。

`verify_fixes` 会把 `retime_curve` 单列成「待复测」，既不算通过也不算失败：
它动的是时间不是文本，「0 失败」不能替它背书。

---

## 结案条件

| 项 | 判据 |
|---|---|
| L0 结构 | PASS 或已逐条解释 |
| 音频判据 | PASS，或报告明写 UNVERIFIED 及原因 |
| 凭据 | 存在、未过期、`patched_at ≤ computed_at` |
| 回滚可用 | `log.jsonl` 有对应 `retime_curve`，`backups.jsonl` 能枚举 |

对轴模式**没有「门 1 / 门 2」两道人确认门**——它的改动是整集一致的函数，逐条看没有意义。
但要保留一个等价物：**A3 的 dry-run 预览必须给人看**，那是对轴模式唯一的确认点。
