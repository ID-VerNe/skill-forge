# 标点规范化规则

precheck_punct.py 的中文行标点归一规则。SKILL.md 阶段 2.5 引用本文件。

## 设计来源与差异

规则照搬 translate_principle pipeline 的 `postprocess_translation`（`core/stages/polish_stage.py`、`post-process/02-post_process_ass.py::clean_single_line`、`core/srt_utils.py::clean_content`），但有**关键差异**：

- pipeline 的规则用于**翻译产出阶段**——刚翻译完的中文行，没有"主修 agent 有意加的译注"。
- skill 的 precheck 用于**精校阶段**——主修 agent 会加 `(EMU)`/`(机务段)` 这类译注括号，pipeline 的一刀切规则会删掉。

所以 skill 的 precheck 在 pipeline 规则基础上加了省略号感知、注释括号收窄、缩写点保护三条修正。

## 规则（按应用顺序）

### 0. 省略号感知（点号删除之前）

在下面的"非数字间英文点删空格"规则之前，先把 `...` 当省略号处理，不当英文点：

- CJK 后接 `...`（尾）：`CJK...` → `CJK…`
- 行首 `...` 紧跟 CJK：`...CJK` → `…CJK`
- 数字间 `37...37403`：按用户意图也→ `37… 37403`（车号口误自纠的省略号）

这样 `我的...` → `我的…`（半省略号），而非被当 3 个英文点删成空格再合并成 `我的`。

### 1. 全省略号归一

`……` → `…`（半省略号）。

### 2. 中文标点删空格

`，。、` → 空格（中文逗号/句号/顿号在成品里应已转空格，残留的删）。

### 3. 非数字间英文点删空格

`(?<!\d)[.,](?!\d)` → 空格。保护数字间的 `.`/`,`（如 `3.14`、`1,000`）。

**缩写点保护**：`字母.字母` 模式（如 `J.R. 哈特利`）的点不删——加负向断言，`[A-Za-z]\.[A-Za-z]` 中的点保留。否则 `J.R.` 被删成 `J R`。

### 4. 多空格合并

` {2,}` → 单空格。

### 5. 连续横杠合并

`-\s*-+` → `-`。

### 6. 注释括号删除（收窄）

只删**中文注释括号**：`（注[：:].*）`、`（旁白.*）` 这类泄漏进正文的注释。

**保留**：
- 带英文大写字母的括号 `(EMU)`、`(机务段)` ——主修有意加的译注
- 纯数字括号 `(3.14)` ——已是数字保护
- 一般中文括号 `（虚构）`（如不是注释格式）——译注用，保留

收窄正则：`re.sub(r"[（(]\s*注[：:].*?[）)]", "", body)` + `re.sub(r"[（(]\s*旁白.*?[）)]", "", body)`，而非 pipeline 的 `re.sub(r"[\(（][^\)）]*[\)）]", "", body)`（后者删所有括号）。

## 不动

- 英文行：源片台词，连续空格/`--`/`...` 是口语特征，不检查。
- 前导 ASS 标签（`{\be3}` 等）：保留，只对可见文本应用规则。
- `! ！ ? ？ ; ； ' " ‘ ’ “ ” …`：保留。
- 数字间的 `.`/`,`：保留（`3.14`、`1,000`）。

## 报告不覆盖

`precheck_punct.py --accept` 不重写 `precheck-punct.md`（dry-run 报告）。accept 模式：
- 若要验证 accept 后干净，写到 `precheck-punct-accept.md` 或不写报告。
- 保留 dry-run 那份 `precheck-punct.md`，事后可查 precheck 原本报了什么。

## 只查中文行

英文行是源片台词，不查标点。中文行通过 `style_to_track(e.style) == "中文"` 判断（ass_srt_pair.style_to_track）。
