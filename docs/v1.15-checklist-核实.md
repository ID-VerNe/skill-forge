## 1. 答复判断有误的两处

### 1.1 问题 2「A-2 标签名不符」→ **不是文档不一致，是我清单漏写**

答复说：清单只点了 `PAIRING_OUT_OF_TOLERANCE` / `PAIRING_FAILED`，漏了 `BOUNDARY_OFFSET`，「归属：skill 文档/清单不一致」。

**对，但归因错。** `BOUNDARY_OFFSET` **不在 `f7f77e0` 里**，是未提交补丁新增的第三个标签。核：

```
$ git show HEAD:scripts/lib/ass_srt_pair.py | grep -n "BOUNDARY_OFFSET"
（无输出）
$ grep -n "BOUNDARY_OFFSET" scripts/lib/ass_srt_pair.py
534:  anomalies.append(f"BOUNDARY_OFFSET(off={near:+.2f}s)")
```

所以清单没写它**是正确的**——被测代码本就不该有它。答复这条应改为「无法判定（被测代码非基准版本）」。

### 1.2 问题 3/14「标签只在头注、正文末列恒空」→ **把 `note` 列误读成「预留的标签列」**

答复最重的一条是：

> 正文行是 `srt_id | start-end | 英文 | 中文 | <空> |` —— 5 列，末列为空
> 「疑似为『异常标签列』预留但未写入」→ 归属 skill 设计缺陷

**实测不成立。** 末列是 `pb.note`，一直存在，不是标签列：

```python
# extract_slice.py:220-225
def format_block_line(pb) -> str:
    """一 block 一行。"""
    english = pb.english or ""
    chinese = pb.chinese or ""
    note = pb.note or ""          # ← 末列
    return f"{pb.srt_id} | {pb.ass_time} | {english} | {chinese} | {note}"
```

`note` 为空的时候，行尾自然是 ` | `。补丁后所有块都走顺序映射，`note` 一次都没被赋值 → 全片末列恒空。**这是补丁的副作用，不是「预留未写入」。**

### 1.3 但问题 3 的**实质论点成立，而且是我清单没考虑到**

答复剥掉误读后，剩下的话是对的：

> 标签只在头注，审计员逐行读正文时看不到标记

这句话值得单独记。`pipeline-spec.md` 里写的是「切片头注可能含异常标记」，`audit.tmpl` 也是让 agent 读头注。**但 v1.13 之后审计是「通读正文」的**，正文里没有任何标记位，`note` 列虽然存在却从没被用来放标签。

→ 我这边记为一个开放项：**标签的可见位置是否该从「头注」挪到「行内 `note` 列」**。这是设计判断，不是 bug，等你定。

## 3. `会话问题汇总.md` 里我认为最该先处理的三条

这份报告的 11 条核验「7 成立 4 部分成立 0 假」，质量很高。按我的判断排序：

### P0-1 · `_row_group_texts` 与 `read_current` 锚点语义不一致（第 4 条）

`_row_group_texts`（`apply_fixes.py:244,251`）用 **SRT 起点 + 0.5 s**，`read_current`（`lib/current.py:153-155`）用 **ASS 起点 + 0.002 s**，两者相差中位 3.08 s。

后果不是「报错」而是**合法的 `current` 被判「不在行组」→ 告警后被覆盖成回读值**，`run_accept` 直接抵消 `index_align` 的收益。这比第 1/3 条更隐蔽，因为日志里只看到一条告警。

### P0-2 · `except Exception` 三处吞异常（第 11 条 + 清单外那处）

`cross_check.py:67-72` 吞掉后 `align={}` → en/zh 全空 → **撞车统计恒为 0，报告看起来干净**。该文件 `:60-62` 自己的注释就警告过这个后果。这是「静默致报告失真」的典型，比写错行更难发现。

### P0-3 · 第 6 条建议被答复自己纠正了，纠正得对

原文建议 5 处 `<= 0.5` 收紧到 `0.05`。答复实测：0.5 → 495 无命中 / 142 对 / **232 错行**；0.05 → 810 无命中 / 33 对 / 26 错。**收紧等于把「静默写错」换成「大面积定位失败」**。正解统一走映射。

这条纠正很关键——照原建议改会得到一个「看起来更严格、实际更不可用」的版本。
