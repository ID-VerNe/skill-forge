## 0. 先纠正三处误判

动手前先把这三条钉死，否则会照着错的方向改。

### 0.1 ❌ 报告说「R11 顺得可疑，因为它是确定性扫描」——**这条建议会拆掉整个 v1.13**

报告 §4.5 与 §7.4 把 R11 的顺畅归因于 `scan_inclusive.py` 是确定性扫描器，并据此暗示前 7 类也应该走词表驱动。**这正好是 v1.13 花整版改掉的结论。**

R11 顺，不是因为它有扫描器，是因为：

| 真实原因 | 与扫描器无关的证据 |
|---|---|
| 7 条全部落在**单词级 L1**（`天啊`→`天呐`），改法不需要看上下文 | 同一份词表在 R1–R10 的语境题上一条都没贡献 |
| 有 `whitelist` 兜底，判断成本接近零 | 白名单是**防误改闸**，不是召回放大器 |
| 改动量小（7 条），裁决→dry-run→verify 链条短 | 前 7 类动辄 20–30 条、含整句重写 |
| 我作为主 agent 把 `scan_inclusive` 的输出**又过了一遍 LLM 判断** | 报告 §4.5 把这一步算成了扫描器的功劳 |

**保留 v1.13 的核心裁决**：判断归 LLM，脚本只定位。本 issue 不推翻它。

真正该记的是反面教训：**R9（第 7 类）没有任何定位工具**，只能靠 LLM 通读 25 条建议里 21 条被采纳却全部悬空（H1）。这说明「定位」这一层不是太多，是**不够**——但补定位 ≠ 让脚本下判断。两件事要一起说清楚，否则下一个人会误读成「回到词表驱动」。

### 0.2 ❌ 报告说「中文整体早一句 + 英文逐级漂移」是输入缺陷——**已修，现在是干净的**

复核 `S06E01.eng.ass`（728 中 / 728 英）：

```
同索引 start delta:  min 0.00  max 0.00  p50 0.00
中文末条 2627.88s / 英文末条 2627.88s
第 371 行  EN: by selling the Smallest Cog racecar, the MGB GT.
          ZH: 通过出售小齿轮修车房那辆赛车 MGB GT
```

中英逐条严格对齐，`#371` 残片已删，`retime_to_srt.py` 已把英文轨重写到 `max|ass_en − srt| = 0.00`。

**所以这两条不是「设计缺陷」，是「输入本来坏 + skill 没有发现它的工具」。** 修复目标要改写成：**给用户一个在开工前 10 秒内能发现「轨错位/残片/漂移」的检查器**，而不是「让 `precheck_timeline` 能抓语义错位」（它做不到，也不该做）。

### 0.3 ⚠️ 报告说「L0 只能证伪结构，抓不到语义错位」——对，但结论要收窄

`precheck_timeline` 判 PASS 是**正确的**：条数相等、时间单调、包络合理，它没有说谎。问题在于**没有人承诺过它管内容对位**，而文档里也没写明「L0 PASS 不代表什么」。

修法不是给 L0 加语义检查（那会把它变成一个又慢又不准的巨物），而是 **L0 报告里必须写清「本检查只管这 4 件事，以下 3 类问题它看不见」**，并在 §2.2 补一个独立的中英对位检查器。

## 2. 分批实施计划

### 批次 A：交付端（P0，必须修，否则产出错结果）

#### A1. optional-fixes 入账不落盘（H1 + M7）

**现状**：`round_orchestrator --record r09 --batch-id "" --n-fixes 0` → 25 条建议里 21 条被采纳，成品不动、台账不记、`verify/cross_check/regression` 全看不见。报告教的 `apply_fixes` 命令从未被执行过。

**改法**：拆成两个显式动作，不允许含糊的「默认不落盘」。

```
optional-fixes.json          仍是「候选项池」，status: proposed|accepted|rejected
       │  --promote 显式提升
       ▼
log.jsonl    batch_id=<stamp>_r09, applied=false, status=accepted
       │  verify / cross_check / regression 现在能看见它
       │  apply_fixes --apply-batch <stamp>_r09 才真的改盘
       ▼
成品 ASS
```

- `optional-fixes.json` 每条新增必填 `srt_id` / `current`（**从 ASS 回读，不从审计 JSON 抄**，见 A2）
- `--record` 时若该轮产出过 `optional-fixes.json` 但未 promote，manifest 里记 `verdict: "advisory"`，**报告必须单列一节说明「本轮 N 条建议未落盘」**，不许静默
- `optional-fixes.md` 由 json 渲染生成，**两者同源**，`t_optional_md_in_sync` 交叉校验

#### A2. 生成 fixes 的脚本一律回读 current（H2 半修）

**现状**：`make_fixes_r11.py:35 cur = zh[srt_id - 1].text` 直接抄审计 JSON 里的 `current`。审计员把 #369 写成「别太生意人」时，`current` 和 `suggested_new` 一起被污染，dry-run 只能对比两个 LLM 产出，看不出原文语义。

**改法**：`fixes.json` 里 `current` 字段**降级为「审计员看到的原文」仅供参考**，真正落盘用的 `current` 一律从 ASS 按 `srt_id` 回读。

```
修复前：  fixes.json.current  ──────────────► apply_fixes
修复后：  fixes.json.suggested_new ──┐
          ASS[ srt_id ] ────────────┴──► apply_fixes（current 由脚本回读）
```

配套：`srt_id` 必须落在 `1..len(rows)` 内，越界**直接 reject 并计入 `bad_id` 统计**，不许静默跳过（M2）。

#### A3. apply_fixes 语义护栏（H2 另一半）

**现状**：`别太生意人` vs `businesslike about it`，dry-run 无警示。

**改法**：在 dry-run 阶段跑三个廉价判据，任一命中即**强制该条 `requires_confirm: true`**，批量 accept 时跳过、单独列出：

| 判据 | 例 |
|---|---|
| 否定/反向词对出现（`别` `不` `没` `无需` 新增或消失） | `用商业思维` → `别太生意人` |
| 编辑距离 > 60% 且原句 < 15 字（整句重写） | 短句被整句换掉，多半是重新创作 |
| 新增/删除了数字、专名、`RS2000` 这类标识符 | 事实性 token 变更 |

**这条不能代替 LLM 判断**——它只负责「把可疑的挑出来逼人看一眼」，不负责说这一定是错的。

#### A4. 孤儿 log 清理 + `--work-dir` 收敛（H4 + M1）

- `--work-dir` **只允许一个默认值** `.subtitle-polish`。传 `.` 或绝对路径时**报错退出**，错误信息里给出正确写法
- 所有脚本启动时检查 `<work-dir>/log.jsonl` 与 `<cwd>/log.jsonl` 并存的情况，**直接 abort** 并提示「发现孤儿台账，请先 `--adopt` 或删除」
- 新增 `--adopt`：把孤儿 log 合并进主台账后删除孤儿（合并要按 `ts` 排序、保留 `batch_id`）

> ⚠️ 这条要在**用户已经跑脏的目录**上生效，所以必须给 `--adopt` 出口，不能只是「报错不许跑」。

### 批次 B：可回滚性（P0–P1）

#### B1. `--auto` 隔离 log 必须回写（H3）

**现状**：`_record` 里 `working/log.jsonl` 优先、没有则拷主 log；但 `--auto` 跑完没有归并步骤，导致 74 条掉到 2 条。

**改法**：`--auto` 结束时强制 `merge working/log.jsonl → <wd>/log.jsonl`，并**逐条断言「主 log 行数 ≥ 起点行数 + 本轮新增」**，不成立直接 abort。

#### B2. 结构性改动强制进 manifest（H6）

`retime_curve` / `delete` / 手工 `Edit` 兜底，三类改动**必须**有 batch 条目，否则 `--record` 拒绝通过。`--manual-log` 已经是这个思路，把它从「例外」提升为「唯一入口」。

#### B3. 修正 `_rollback_cmd`（H5）

复核：`apply_fixes --rollback id=<srt_id>` **是存在的**（L12），但 `_rollback_cmd(ass, chat_id)` 传的 `chat_id` 是批次标识，不是 `srt_id`。所以报告里生成的 `--rollback id=20261102_074133` 语义错位。

**改法**：报告生成**两个**命令，都标明适用范围：

```
整轮回滚:  apply_fixes.py --rollback batch=<batch_id>
单条回滚:  apply_fixes.py --rollback id=<srt_id>
```

并且**所有写进报告的命令必须来自「本次实际执行过的调用」**，不许手拼字符串。

#### B4. 双 run 的回滚隔离（报告 §2.9）

复核**与报告描述不同，但问题更隐蔽**：

```
runs/20261102_r9r11/logs/r00.jsonl   124 行   ← 起点（R1–R8+R10 的账）
runs/20261102_r9r11/logs/r09.jsonl   131 行   ← 已含 R11 的 7 条
runs/20261102_r9r11/logs/r11.jsonl   131 行
.subtitle-polish/log.jsonl           131 行   ← 主台账
```

`r09.jsonl` 落在 R11 **之后**（因为 R9 先跑、R11 后跑，但 `--record r09` 是在 R11 落盘后才补记的）。所以回滚到 `r09` **不会**丢掉 R11——报告这条说错了。

但它暴露了更糟的问题：**`r0N.jsonl` 快照的语义是不可信的**。

- `r09.jsonl` 名义上是「R9 结束时的台账」，实际包含了 R11 的改动
- 真正干净的时刻是 `r00.jsonl`（124 行），可它叫「起点」
- 也就是说 **`--rollback-to r09` 会把成品的时间轴和文本回退到「R9+R11 都做过」的状态**，这不是任何一个真实存在过的历史时刻

报告里说的「`r03.ass` 这类快照文件根本不存在」是真的，但同一条里「快照全是空串」不成立（`r00.jsonl` 有 124 行真实内容）。

**改法**：
1. `logs/rNN.jsonl` **只允许在 `--record rNN` 的那一刻写一次**，之后禁止覆盖。`--record r09` 在 R11 之后补记时，必须拒绝并报错：「r09 的台账快照已被 r11 越过，无法补记」
2. 快照文件名带上 `batch_id`，`r09_<batch_or_none>.jsonl`，让「这一轮到底改了没有」在文件名上可见
3. `--rollback-to` 前先打印「将还原到 X 行 / 当前 Y 行 / 影响 Z 条」，**要求 `--yes` 确认**
4. 双 run 之间共享主台账时，`--rollback-to` 需要显式 `--run <stamp>`，禁止跨 run 推断

### 批次 C：定位与检测（P1）

#### C1. `structure_check.py`：无 ASR 的中英对位粗检（§0.2 的正解）

这是本 issue 唯一真正的新能力，也是最值钱的一条。**不依赖 ASR**，秒级：

| 检查 | 判据 | 能抓到 |
|---|---|---|
| 轨条数 | 中英条数不等且差 > 1 | 缺行/多行 |
| 索引时间差 | 同索引 `|zh.start − en.start|` 的**分布**：p50 > 0.5s 或 max > 5s | 整轨平移、阶跃 |
| 残片重复 | 中文某行与上一行/下一行**相似度 > 0.9**（去标签后） | `#371` 这类重复残片 |
| 时长异常 | 单条 `dur > 10s` 或 `< 0.2s` | 合并/误切 |
| 跨轨对齐 | 中英末条时间差 > 5s | 累计漂移 |

**判据只输出观测值 + SUSPECT，不给修法**。它不是 `align_audit` 的替代品（对不了音频），是它的**前置筛查**：先保证「轨没坏」，再谈「轴准不准」。

#### C2. `extract_slice` 空块即 abort（M4）

`nonempty == 0` 或**非空率 < 50%** 时直接 abort，错误信息必须包含：

```
[!] p4 nonempty=0（728 块里 0 块匹配到英文）
    这通常不是「提词器段落」，先查三件事：
      1. 时间轴容差（默认 TIME_TOLERANCE=0.5s）是否小于实际漂移
      2. 中英轨是否错位（跑 structure_check.py）
      3. 该段是否真的无对白（抽 3 个块人工对照视频）
```

R1 因空切片作废重跑 11 次审计，这条能直接省掉。

#### C3. `scan_inclusive` 报表加 `srt_id`（M2 的一半）

报表现在是 `| L2 | 天啊 | 128.92s |`，列头「时间」、首列「层」——**都不是 srt_id**，`make_fixes` 拿 128 当索引直接 `IndexError`。

改成：
```
| srt_id | 层 | 命中 | 时间(秒) | 现译 | 文件 |
| 41     | L1 | `天啊` | 128.92  | 天啊，伙计 | e01.ass |
```

一行改动，省每个使用者 5 分钟。

#### C4. `show_ids.py` 内置（报告 §4.2）

批量打印 `srt_id → 英文 / 中文 / 时间`，供裁决时逐条核对。这是每轮都用得上的动作，不该每次临时写。

#### C5. 给前 7 类补定位（H1 的根因）

R9 零定位工具 → 25 条建议全靠 LLM 通读 → 21 条采纳却悬空。`scan_seed.py` 现在只扫第 8 类形态。

**改法**：给 `scan_seed.py` 加 `--mode category7`，锚点改为**形态**而非词：句末语气词堆叠、书面连接词（`则/于是/因此`）、四字成语密度、与英文长度比异常（中/英 > 3.0 或 < 0.6）。

**再次强调**：输出仍是锚点，不是判据。`instruction` 段不变。

## 5. 明确搁置的

### 5.1 D 子域死亡表达：不修，且不设"以后再说"的钩子

`passed away` → 「嗝屁」这一条，**决定是不做**。理由不是"优先级低"，而是**收益不存在**：

- 国内字幕受众的投诉集中在地域、性别、职业刻板印象（A/B 子域），死亡表达不在其列
- `passed away` / `died` / `gone` 的中文对等词在绝大多数语境下没有争议译法，硬加一层「讣告语境检测」属于给一个不存在的需求造机器
- 唯一有争议的「嗝屁」「蹬腿」这类是**风格选择**，不是合规问题。同一个人说 `passed away`，旁白该译「去世」、葬礼上的醉汉该译「嗝屁」，这恰好是 LLM 通读能判、脚本永远判不了的东西

> 措辞注意：文档里**不要**写「国内打拳的大概率不会管这个」。「打拳」是被污名化的网络标签，
> 写进 skill 文档等于替挑刺者站台又反手踩一脚，两边都不体面。要表达的是**事实**：
> 国内受众的投诉集中在 A/B 子域（地域、性别、职业刻板印象），死亡表达不在其列。

**所以：D 子域保持"锚点出现即列出、agent 自行判断"的现状，不加规则、不写进 backlog。** 如果哪天真实投诉出现，再作为新 issue 开。
