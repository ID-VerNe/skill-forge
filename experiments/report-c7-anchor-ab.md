# 第 7 类形态锚点实测：2×3 对照报告

> 目的：回答 issue #24 的 C5 待决项——**要不要给 `scan_seed.py` 加 `--mode category7`（形态锚点）**。
> 方法：E02 / E03 / E04 三集 × A（无锚点，通读全文）/ B（形态锚点 + 通读全文）。
> 结论先行：**不做。锚点在这批真实数据上的召回增益约等于 0。**

---

## 1. 实验设计

| 项 | A 臂（对照） | B 臂（实验） |
|---|---|---|
| 输入 | 整片中英轨 | 整片中英轨 **+** 锚点清单 TSV |
| 锚点 | 无 | 有（形态判据扫出的可疑行） |
| 判据 | `fluency-rubric.md` 第 7 类 | 同左，**完全相同** |
| 纪律 | — | 锚点只表示「出现了某种形态」，**不表示「这里是问题」** |

关键设计点：**两臂都通读全文**。如果只让 B 臂看锚点行，比的就是「锚点 vs 全文」，
那结论必然是「全文更好」，测不出锚点的价值。两臂都读全文、B 臂额外拿锚点，
测的才是「锚点能不能帮人看到原本会漏掉的东西」。

---

## 2. 锚点密度（成本侧）

锚点判据历经两轮修正，每一轮的结果都暴露了上一轮的问题：

### v1：单字正则（`min_hits=3`）→ 1 行
`文言残留` 用了单字 `(之|其|乃|亦|俱|皆)`。抽样一看全是误报：
「其**实**」「之**一**」「**其**他」在自然汉语里高频出现，单字匹配等于噪声。
三集 2386 行只锚出 1 行。

### v2：降到 2 命中 + 词组级 → 20 行（但含假阳）
把 `所谓文言残留` 改成词组（`颇为/甚为/可谓/不失为/而已/矣`），去掉单字，
`min_hits` 降到 2。三集锚出 20 行（0.8%），形态分布：
`文言残留 11 / 系词冗余 13 / 长度比 16 / 语气堆叠 4 / 书面连接 1 / 被动欧化 2`。

**但 E03 的锚点全是假的。** 抽样立即发现：
```
#443  长度比,系词冗余   呃 看着是一团糟 那是因为它本来就一团糟
      EN: Brown ones, get rid of them.
```
中文和英文根本不是同一句话。

### 根因：E03 中英轨下标错位
```
S06E02: 英=869 中=869  时间不匹配 0/869   最大差 0.00s   ✅ 完全对齐
S06E03: 英=763 中=767  时间不匹配 615/763 最大差 39.84s  ❌ 错位
S06E04: 英=750 中=750  时间不匹配 0/750   最大差 0.00s   ✅ 完全对齐
```

E03 从第 149 行起，中文轨多出一条零时长碎片（`#149 "是的"`，起点与 `#148` 相同
`430.72s`），后面所有行整体错开一位，偏差一路累积到 39.84 秒。
中文轨还比英文轨多 4 行（尾部含 `字幕由 Deluxe 提供` 版权行）。

**用下标配对算「长度比」，会把两个不相关的句子拼在一起比较，制造 100% 假锚点。**

### v3：按时间戳配对 + 跳过零时长碎片 → **1 行**
修正配对逻辑后重跑：

| 集 | 行数 | 锚点行 | 占比 | 形态 |
|---|---|---|---|---|
| S06E02 | 869 | 1 | 0.1% | 系词冗余 + 名物化 |
| S06E03 | 767 | **0** | 0.0% | — |
| S06E04 | 750 | **0** | 0.0% | — |
| **合计** | **2386** | **1** | **0.04%** | |

那唯一一条真锚点：
```
#854  这是一项国际性的工作
      EN: it is an international job
      hits: 系词冗余(是[一个位种名场]) + 名物化(性...的...)
```
**这是一个好锚点**——`it is an international job` 译成「这是一项……的工作」确实是
典型翻译腔，「国际性的工作」也偏书面。锚点抓对了。

但**一条**。

## 3. 为什么锚点密度上不去：不是参数问题，是样本问题

继续调参之前先看数据本身长什么样：

```
S06E02: 中文均长 11.7 字  英文均词 7.7  比值中位 1.50  P90 2.00
S06E03: 中文均长 12.8 字  英文均词 8.3  比值中位 1.40  P90 2.75
S06E04: 中文均长 13.3 字  英文均词 8.7  比值中位 1.50  P90 2.00
```

**中文均长 11.7–13.3 字，中英比值中位 1.4–1.5。** 字幕的物理约束决定了它必须短，
这批译文本身也相当贴原文、相当口语化。再看各形态的真实出现率：

| 形态 | E02 | E03 | E04 | 三集合计 |
|---|---|---|---|---|
| 书面连接（则/因此/然而/并且/从而…） | 2 行 | 2 行 | 1 行 | **5 行** |
| 文言残留（颇为/甚为/可谓/而已/矣…） | **0** | **0** | **0** | **0 行** |
| 被动欧化（受到/得以/加以/予以） | 0 | 0 | 1 | **1 行** |
| 系词冗余（是[一个位种名场]/进行的） | 32 | 26 | 26 | 84 行 |
| 「四字堆叠」正则 `[\u4e00-\u9fff]{4}` | 492 | 481 | 484 | **1457 行（61%）** |

两件事说清楚了：

1. **文言残留 0 次，被动欧化 1 次，书面连接 5 次。** 这些形态在真人秀口语旁白里
   就是不存在。锚点抓不到东西，不是因为阈值严，是因为**样本里没有**。

2. **「四字堆叠」正则是个坏判据。** 它匹配了 61% 的行——因为
   「小齿轮修车房」「虽然很舍不得」「打算卖掉」都是四个汉字连排。
   这不是「四字成语堆叠」，是汉字文本的常态。第一版我主动跳过它是对的，
   但**跳过之后没有设计出替代品**，等于这个维度完全空缺。

3. **系词冗余 84 行看起来有料，实则精度堪忧。**「这正好是个机会」「那是一辆非常
   罕见的古董车」——`是[一个位种名场]` 命中的绝大多数是自然的「是+量词」结构，
   不是欧化冗余。真阳性率大概就是这个 1/84。

## 4. 2×3 判定

| | A 臂（无锚点） | B 臂（锚点） |
|---|---|---|
| **E02** | 通读 869 行 | 通读 869 行 + 1 条锚点 |
| **E03** | 通读 767 行 | 通读 767 行 + **0 条锚点**（= 完全退化为 A） |
| **E04** | 通读 750 行 | 通读 750 行 + **0 条锚点**（= 完全退化为 A） |

**在 3 集里，有 2 集的 B 臂与 A 臂输入完全相同。** 这个对照在结构上就是无效的
——不是「B 略差」，是「B 根本没有被施加处理」。

即便 E02 那 1 条锚点，A 臂通读全文时也**必然会看到这一行**（它是第 854 行，
在通读范围内）。所以 B 臂相对 A 臂的**真实增量 = 0**。

## 5. 结论

### C5 定案：不做 `--mode category7`

理由不是「做了没用」，而是更根本的一条：

> **形态锚点没有提供任何 A 臂通读之外的信息。**

因为两臂都通读全文，而锚点是从同一份全文里扫出来的子集。只要子集的召回没有
超过「人通读一遍的注意力」，它就不产生增量。这批数据上子集大小是 0.04%，
且其中含大量假阳（v1 的文言单字、v2 的 E03 轨道错位）。

### 更重要的发现：不做锚点，但要修轨道

这次实验原本是要测锚点的，却**测出了一个真 bug**：

**E03 的中文轨从第 149 行起整体错位，最大偏差 39.84 秒，原因是中文轨有一条
零时长碎片行。**

这个问题的性质：
- 它**不是翻译问题**，任何 LLM 审校都发现不了（LLM 看到的是「这句话译得好不好」，
  不是「这句话和英文是不是同一句」）
- 它**会污染所有需要中英对照的判据**：长度比、漏译检测、语气词还原、
  `check_fluency.py` 的「英文没有对应来源」对照——全部失效
- 它是**确定性的、开工前一次性就能查出来的**

所以报告 §2.5 的判断是对的，但**要修正它的落点**：不是给 `precheck_timeline`
加语义检查，而是**新增一个开工前的轨结构检查器**（`structure_check.py`），查四件事：

1. 中英轨行数是否相等（E03: 767 vs 763 ❌）
2. 逐行时间戳是否对齐（≤0.05s，E03: 615/763 行超标 ❌）
3. 是否存在零时长行（E03: `#149` 起点与 `#148` 相同 ❌）
4. `track` 字段是否为合法值（E03: `中nning? It's runni文` ❌）

这四条命中任意一条，**直接阻断开工**并报出具体行号。

## 6. 对 issue #24 的影响

- **C5 关闭**：`scan_seed.py` 不加 `category7`。锚点这条路在真实数据上不成立。
- **C3 升级为 P0**：新增 `structure_check.py`（开工前轨结构检查），理由见 §5。
  它比 C3 原定的「定位与检测」问题更硬——它能让整轮审校的结果全部失真。
- **`check_fluency.py` 的书面语规则表**：`文言残留` 这一整类（颇为/甚为/可谓/而已/矣）
  在三集 2386 行里 **0 命中**。这条规则要么删掉，要么标注「极低命中，勿单独依赖」。
  按 issue #7 的纪律（判据是「中文出现该词且英文没有对应来源」），留着不害事，
  但不能算进「覆盖面」。
